## Implemented

- Optional GA4 loading only after explicit consent, on the production origin, and on allowed storefront routes. No Google script is requested before consent by this integration.
- Equally styled Accept and Reject actions, persistent versioned preferences, expiration after 180 days, footer preferences, immediate withdrawal, storage-failure handling, and Global Privacy Control support.
- Ads storage, ad user data, personalization, and Google Signals are disabled. No advertising tags are added.
- Manual `page_view`, `view_item`, `add_to_cart`, `remove_from_cart`, `view_cart`, `begin_checkout`, and `purchase` events.
- Query strings, fragments, checkout session IDs, form fields, customer details, destination URLs, logos, and private account/admin/hosted pages are excluded from event payloads. Known search/social referrers are reduced to their origin; unknown referrers are omitted. Campaign query parameters are not collected.
- Category and solution detail pages are grouped in GA4 to avoid copying arbitrary route values. Existing catalog product paths are allowed. The existing internal NFC tap analytics module remains unchanged.
- Purchase data comes from the persisted paid live order, not the redirect URL or cart. USD item totals must reconcile with the stored total after tax and shipping. Unpaid, manual, test, inconsistent, and reversed orders are excluded.
- The first Multi-Link charge is included when recorded and reconciled; future renewal revenue is not fabricated or tracked by this browser integration.
- A stable order UUID, persistent browser marker, in-memory guard, and browser Web Lock where supported reduce duplicate purchase dispatch. GA4 also receives the same transaction ID. Storage failure suppresses purchase dispatch.
- Pending live payment confirmation retries for up to one minute while the success page is open and analytics is permitted. No new public order-data API was added.
- Updated privacy disclosure and optional Search Console HTML verification metadata.

## Configuration Gates

Server environment variables (see `.env.example`):

| Variable | Purpose |
| --- | --- |
| `GA4_MEASUREMENT_ID` | Real web stream ID, `G-...` |
| `GA4_ENABLED` | Must explicitly be `true` to enable optional measurement |
| `GA4_MANUAL_EVENTS_CONFIRMED` | Must be `true` only after the Google stream settings below are verified |
| `GOOGLE_SITE_VERIFICATION` | Optional HTML verification token for a URL-prefix property; unnecessary for DNS verification |

`/api/site/analytics-config` returns only the public ID and allowed origin, with no-store caching. Invalid/missing settings disable GA4. Localhost and preview domains cannot send events to the production property. Temporary local UI test settings were removed; the endpoint again returns a null measurement ID.

The isolated build uses Webpack because Turbopack cannot follow the shared dependency junction outside its build root. Build with production-origin environment overrides plus `NEXT_PRIVATE_STANDALONE=true` and `NEXT_PRIVATE_OUTPUT_TRACE_ROOT` set to the release directory, run `npx next build --webpack`, then `npx opennextjs-cloudflare build --skipNextBuild`. It includes local environment inputs and must not be committed or shared.

Ad blockers, users leaving before webhook confirmation, denied consent, transport failures, or blocked storage can cause undercounting. A local dispatch marker does not prove delivery to Google. Use the orders database/Stripe for authoritative revenue; recurring invoices and refunds are not instrumented here.
- Cart analytics resolves known catalog products. Server-confirmed purchase totals are authoritative; new admin-only product slugs and future catalog/pricing changes require measurement regression checks.
- Real Google ownership and the settings listed above are verified. Sitemap acceptance, Google-received events, Search Console-to-GA4 linking, purchase key-event configuration, and live purchase measurement remain unverified. Do not report this phase as 100% complete.
